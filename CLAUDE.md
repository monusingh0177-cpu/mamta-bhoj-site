# Mamta Bhoj Site — Workflow Instructions

## Git workflow

- Work directly in this existing repository.
- Never create a new repository.
- Never change the origin remote.
- When a code change is requested, implement it in the existing project.
- Test the application after changes.
- Review `git diff` before committing.
- Never commit `.env` files, passwords, API keys, tokens, private keys,
  credentials, customer enquiry data, newsletter data, logs, or other
  secrets/PII.
- Stage only the intended files.
- Create a clear commit message.
- Commit the changes.
- Push the commit to `origin/main` after successful testing.
- If a destructive operation or potentially irreversible change is
  required, ask first.
- Keep the existing functionality unless explicitly asked to change or
  remove it.
